# Active Heat Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give authored risky resolutions visible Heat consequences and one explicit, time-costly way to reduce Heat, while deleting inert Alerts.

**Architecture:** Keep `GameState` as the only state owner. Contract catalog records hold the new mutually exclusive Silent Partner choices; existing choice filtering enforces them. Home sends an intent through Main for a guarded 24-hour GameState action; old saves ignore the removed Alerts field without a version bump.

**Tech Stack:** Godot 4.7.1, GDScript, Control scenes, the existing SceneTree test harness and PowerShell runner.

## Global Constraints

- Approved source of truth: `docs/superpowers/specs/2026-09-29-active-heat-design.md`. Do not implement the broader speculative sweeps/raids in `feature-ideas-*.md`.
- No new dependencies, autoloads, phases, generic price multipliers, or persistent exposure meter.
- Keep the single-profile format at version 4 and retain v1–v3 migrations. Use existing `save_profile()`, `_advance_minutes()`, `_add_message()`, and `push_ticker()` paths.
- Tests must drive actual choices and time transitions; do not test only source strings. Existing persistence tests call `reset_profile()` on `user://operator_save.json`: back up any real profile and its `.tmp`/`.bak` siblings before running them, and restore them afterward. Prefer a separate Godot user-data location for the player-path smoke. Run affected suites after each task, the full suite once after code, and a final smoke.

## File map

- `data/contracts/contract_catalog.gd`: Silent Partner's two authored Heat-gated purchase choices.
- `autoload/game_state.gd`: warning emission, 24-hour recovery, save compatibility, removal of Alerts.
- `scenes/modules/home/home_panel.gd` and `scenes/main/main.gd`: recovery intent/action wiring and live Comms updates.
- `resources/module_registry.tres`: remove the dead rail entry (separator is generated by group changes).
- `tests/test_game_state.gd`, `tests/test_contracts.gd`, `tests/test_panels_basic.gd`, `tests/test_main.gd`, `tests/test_persistence.gd`, `tests/test_module_registry.gd`: existing behavioral seams.
- `README.md`, `context.md`, `next-features.md`: update implementation boundary and completed recommendation after code works.

func go_to_ground() -> bool:
